## 一、这是什么

用户(前端 Vue 学习者,学过 Java 语言基础,零后端经验)在做"用户管理系统"项目(Vue3 + Element Plus + Pinia,前端已完成)。原先的后端 `server/`(Node Express + JSON 文件)是"一句话让 AI 生成的"。现在的目标:**用 AI Agent 工程思路从零重写后端(Spring Boot + MySQL),每一步都理解,并写成简历亮点**。

已确定决策(用户拍板):Spring Boot 3.5.16 + MySQL 8 + 按现有 9 接口契约实现 + 仅本地运行。JDK 17 / MySQL 均未安装。

## 二、教学目标与定位(2026-08-23 两次调整后)

**用户主面前端岗,预判面试"双层拷问",agent 层是主战场** → 学习路径核心调整:

- **第一主线 = AI Agent 工程方法论**(面试差异化竞争点):需求拆解、任务规划、审查 agent 输出、契约驱动验证、迭代复盘。后端只是练这套方法论的载体。
- **第二主线 = 后端"最低必要理解"**:支撑审查 agent 代码 + 面试自圆其说。定义 = 项目里每个文件、每行关键代码都能讲清楚(是什么/为什么/项目里在哪),不是系统学习。
- **下调的深度**:不学 Spring Security 全家桶(手写拦截器)、不碰 JVM、事务只讲概念、不学设计模式。
- **项目定位**:简历写"用户管理系统(全栈,AI Agent 驱动开发)",主线是"会用 agent 高效交付的前端工程师";后端项目 = 证明"我能用 agent 交付完整全栈项目"的证据,不冒充后端工程师。

## 三、教学规划(8 阶段,每阶段独立可验证)

### 主线一:Agent 工程工作流(每个阶段固定五步循环)

```
①概念课(大白话+比喻,类比前端已有知识)→ 用户确认理解 → 
②需求拆解(拆成 3-5 个可独立验证的小任务)→ 用户批准 →
③Agent 实现(每写完一个文件/接口,解释关键代码)→ 
④验证(启动 + curl + 浏览器,逐任务核对)→ 
⑤复盘双轨:后端概念面试点 + "这个阶段的 agent 故事怎么讲"
```

用户 = 工程师,Claude = agent。**绝不允许一句话生成整个后端,每段代码必须经过用户理解和验收。**

### 主线二:概念知识块(注意每个概念的提问视角 = "面试官问这个我答什么")

### Agent 面试高频问题(前端岗必准备,持续扩充)

- 你和 agent 怎么分工?(我负责需求拆解和验收,它负责实现)
- agent 写错你怎么发现?(契约驱动验证:接口契约定死,curl/前端逐条对)
- 它写的代码你看得懂吗?(拆小任务 + 逐段 review + 让它解释每段)
- 怎么让它保持质量?(约定响应格式/目录结构;阶段里程碑验收)
- 什么时候不用 agent?(反复改不对、业务逻辑需要深度判断时自己动手)
- 用过哪些 agent 能力?(子任务并行、复盘迭代、代码审查、面试模拟)

### 关键契约事实(以前端代码为准,勿信旧文档)

- 端口必须 **3001**(`.env.development` 写死,`vite.config.js` 无 proxy)
- 改密码接口:`POST /api/users/:id/change-password`(旧文档的 PUT 已废弃)
- `PUT /api/users/:id`:权限"管理员或本人",必须**部分更新**(非 null 才覆盖);非管理员改自己时忽略 role/status
- 错误必须带真实 HTTP 状态码(401 触发前端登出)
- `createdAt` 格式 `yyyy-MM-dd HH:mm:ss`(默认会带 T)
- `/api/stats` 字段定死:`total / active / admin / year`
- 首页看板:`GET /api/stats/register-trend?days=30` 连续 N 天补零 `[{date,count}]`;`GET /api/stats/role-distribution` `[{name,value}]`;字段以前端 `src/api/stats.ts` + `src/types/stats.ts` 为准
- 分页:前端 page 从 1 开始,JPA 从 0 开始 → `PageRequest.of(page-1, pageSize)`
- 密码永不泄漏:UserVO(无 password)+ `@JsonProperty(WRITE_ONLY)` 双保险
- CORS 用 `CorsFilter` Bean,Origin 精确 `http://localhost:5173`
- 时区:JDBC `serverTimezone=Asia/Shanghai` + `spring.jackson.time-zone` 同时配
- 预置 15 用户(admin + user1~14,密码 123456,user3/7/11 禁用)与旧后端一致

### 关键技术决策

1. 目录:新建 `backend/` 与前端同级;旧 `server/` 保留作对照,阶段 7 验收通过后再删
2. Spring Boot 3.5.16(3.x 最后版本,报错可搜性最好)+ Java 17;Maven 用自带 Wrapper,免装

### Q10(2026-08-29):"管理看板统计接口(status-distribution / register-monthly),权限给普通用户还是仅 admin?"
**决策**:仅 admin(requireAdmin)。理由:① 前端 `/user/dashboard` 路由守卫已限 admin(router/index.js:82),接口同步加固 = 纵深防御(前端守卫可绕过,接口才是真边界)② 与 Q9 不冲突——Q9 场景是"首页所有登录用户可见",这两个新接口只被管理员看板用 ③ 与阶段 5 RBAC 模式一致。
**实现取舍(技术债)**:`UserService.requireAdmin` 是 private 无法复用,约束"只新增不改现有"禁止动 UserService → StatsService 内复制一份同逻辑(~10 行),后续可抽成公共类。
**agent 故事素材**:① 验证时发现遗留 java 进程占 3001——登录成功但新接口 404 证明是旧代码 → probe 确认身份再 taskkill(复刻 Q9 流程)② **"401 不能证明接口存在"**:AuthInterceptor 对 `/api/**` 未登录请求统一 401,路径不存在也一样(拦截器先于路由匹配)——必须带 token 才能区分 404/200 ③ cmd 无法启动中文路径项目(GBK 编码报"不是内部或外部命令"),用 bash 版 `./mvnw` 直接可用 ④ TaskStop 停 bash 任务后 java 子进程仍占端口,需 netstat+taskkill 补刀 ⑤ status-distribution 顺序:ORDER BY status 升序时"禁用"在前,契约示例"启用"在前 → 改 DESC ⑥ 交叉印证:总 18 = 启用15+禁用3 = admin1+user17;2026-08 count=3 = register-trend 8-27(1)+8-29(2)。

### Q9(2026-08-29):"首页看板统计接口,权限给普通用户还是仅 admin?"
**决策**:两者都允许(任何登录用户可见)。理由:① 与现有 GET /api/stats 完全一致(无 requireAdmin)② 前端首页所有登录用户可见,前端无权限分支 ③ 数量级统计不敏感。**附带决策**:响应 message 沿用 Result.ok 的 "ok"(契约示例写"成功",但改 Result 会影响全部现有接口,前端只判 code,不值)。
**agent 故事素材**:① 端口 3001 被上次会话遗留的 java 进程占用——先 probe `/api/hello` 确认身份再 taskkill,而不是盲目杀进程 ② 验证时发现 role-distribution 的 user=15(预置 14+测试注册 1),与 register-trend 8-27 count=1 相互印证,证明非 0 统计正确——用接口间交叉验证而不是只信单条输出。

### Q7(2026-08-26):"学的不应该是使用 agent 的逻辑吗?""我做的事是不是只有决策/像测试工程师吗?"
**用户两次流程纠偏**(阶段 3 中途),是重要转折:用户感知到"讲代码→写代码→讲代码"是老师模式,不是 agent 工程模式;后续"只让用户跑 curl"又把用户压缩成人肉测试脚本。
**Claude 修正(教学方式重构)**:① 执行性验证(curl/查库)交还给 agent ② 用户只做四类工程师动作:定义验收标准/方案决策/审查推理链/纠偏 ③ 每个任务拆解给"开放选项"让用户选 ④ 复盘用户先讲,agent 补漏。
**效果**:用户认识到"决策 = agent 工程的全部工作",T4 方案 A(精确 CORS)拍板正确(带凭证不允许全放行,A 是唯一可行)。
