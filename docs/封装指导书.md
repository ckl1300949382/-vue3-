## 1. 为什么要封装

打开现在的项目，你会发现大量重复的模式：

| 重复模式 | 出现位置 | 抄了多少遍 |
|---------|---------|-----------|
| 输入框长度限制 + 字符过滤 | `Login.vue` + `Register.vue` | 2 个文件 × 各 2～3 个函数 |
| Enter 键监听 + mount/unmount | `Login.vue` + `UserManage.vue` | 2 个文件 × ~10 行 |
| `res.data.code === 200` 判断 | 每个 API 调用处 | 8+ 处 |
| 表单字段校验（非空、长度） | `Login.vue` + `Register.vue` + `UserManage.vue` | 3 个文件 |
| 分页状态管理（page/pageSize/total） | `UserManage.vue` | 1 份，但写死了 |

**封装的本质：把"做什么"和"怎么做"分开。**

- 组件只关心"我要限制用户输入"（做什么）
- 封装函数关心"怎么限制、怎么清理"（怎么做）

好处：
- 改一处逻辑，所有用到的页面自动生效
- 新页面写同样的功能，一行代码引入即可
- 代码可读性大幅提升

## 2. 封装的基本思路

```
┌─────────────────────────────────────────────┐
│  页面组件 (Login.vue / Register.vue)        │
│  ┌─────────────────────────────────────┐    │
│  │  调用封装好的 composable / utils    │    │
│  │  → useInputLimit()                 │    │
│  │  → useKeyboardSubmit()             │    │
│  │  → request.get()                   │    │
│  └─────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
                      ↕          ↕
          ┌─────────────────┐  ┌──────────────────┐
          │  composables/   │  │  api/user.js      │
          │  复用的逻辑      │  │  请求封装          │
          └─────────────────┘  └──────────────────┘
                      ↕                 ↕
          ┌─────────────────┐  ┌──────────────────┐
          │  Vue 组合式 API  │  │  axios 实例       │
          │  (ref/onMounted)│  │  + 拦截器         │
          └─────────────────┘  └──────────────────┘
```

Vue3 的 **Composable（组合式函数）** 是封装的核心理念 —— 把带状态的逻辑提取成函数，函数内部可以使用 `ref`、`onMounted`、`watch` 等 Vue API。

## 3. Composable —— Vue3 的封装利器

### 什么是 Composable？

一个**利用 Vue 组合式 API 来封装有状态逻辑的函数**。

```js
// 一个简单的 Composable
import { ref, onMounted, onUnmounted } from 'vue'

export function useMouse() {
  const x = ref(0)
  const y = ref(0)

  function update(e) {
    x.value = e.pageX
    y.value = e.pageY
  }

  onMounted(() => window.addEventListener('mousemove', update))
  onUnmounted(() => window.removeEventListener('mousemove', update))

  return { x, y }
}
```

任何组件中都可以这样用：

```js
const { x, y } = useMouse()
// x 和 y 会自动更新
```

### 规则

1. 文件名以 `use` 开头（Vue 社区惯例）
2. 可以接收参数，返回响应式数据或函数
3. 内部可以调用其他 composable（组合）
4. 放在 `src/composables/` 目录下（惯例）

## 4. Composable 实战

### 4.1 `useInputLimit` —— 输入限制

**现状问题**：Login.vue 和 Register.vue 各自写了类似的函数来处理输入长度和字符过滤。

```js
// Login.vue — 12 行重复代码
const handleUsernameInput = (e) => {
  let value = e.target.value.replace(/[^\w]/g, '')
  if (value.length > 20) value = value.slice(0, 20)
  loginForm.value.username = value
}
const handlePasswordInput = (e) => {
  let value = e.target.value
  if (value.length > 20) value = value.slice(0, 20)
  loginForm.value.password = value
}
```

**封装方案**：`src/composables/useInputLimit.js`

```js
import { ref } from 'vue'

/**
 * 输入限制 composable
 * @param {number} maxLength - 最大字符数，默认 20
 */
export function useInputLimit(maxLength = 20) {
  /**
   * 限制输入长度（通用）
   * @param {Event} e - input 事件对象
   * @returns {string} 截取后的值
   */
  function limitLength(e) {
    let value = e.target.value
    if (value.length > maxLength) {
      value = value.slice(0, maxLength)
    }
    return value
  }

  /**
   * 限制输入长度 + 只允许英文、数字、下划线
   * @param {Event} e - input 事件对象
   * @returns {string} 过滤+截取后的值
   */
  function limitAlphanumeric(e) {
    let value = e.target.value.replace(/[^\w]/g, '')
    if (value.length > maxLength) {
      value = value.slice(0, maxLength)
    }
    return value
  }

  return { limitLength, limitAlphanumeric }
}
```

**改造后的 Login.vue**：

```js
// 从 40 行 → 约 15 行
const { limitLength, limitAlphanumeric } = useInputLimit(20)

const handleUsernameInput = (e) => {
  loginForm.value.username = limitAlphanumeric(e)
}
const handlePasswordInput = (e) => {
  loginForm.value.password = limitLength(e)
}
```

同样的方式改造 Register.vue，5 个输入处理函数都能复用。

### 4.2 `useKeyboardSubmit` —— 键盘提交

**现状问题**：Login.vue 和 UserManage.vue 各自写了 Enter 键监听的 mount/unmount。

```js
// 每个文件 ~10 行
const handleKeydown = (event) => {
  if (event.key === 'Enter') handleLogin()
}
onMounted(() => document.addEventListener('keydown', handleKeydown))
onUnmounted(() => document.removeEventListener('keydown', handleKeydown))
```

**封装方案**：`src/composables/useKeyboardSubmit.js`

```js
import { onMounted, onUnmounted } from 'vue'

/**
 * 键盘提交 composable
 * @param {Function} callback - 按下 Enter 时要执行的函数
 * @param {Object} options
 * @param {boolean} options.enabled - 是否启用，默认 true
 */
export function useKeyboardSubmit(callback, { enabled = true } = {}) {
  if (!enabled) return

  const handler = (event) => {
    if (event.key === 'Enter' && !event.shiftKey) {
      callback()
    }
  }

  onMounted(() => document.addEventListener('keydown', handler))
  onUnmounted(() => document.removeEventListener('keydown', handler))
}
```

**改造后的 Login.vue**：

```js
// 从 ~12 行 → 1 行
useKeyboardSubmit(handleLogin)
```

> 💡 **教学点**：这里也可以用 Vue 模板语法 `@keyup.enter="handleLogin"` 替代，但对弹窗中的表单或非焦点场景，全局键盘监听更通用。composable 给了你选择的灵活性。

### 4.3 `useDebounce` / `useThrottle` —— 防抖与节流

**现状问题**：搜索是点击按钮触发的，但如果要做"输入即搜"（实时搜索），不加防抖每次按键都会发请求。

**封装方案**：`src/composables/useDebounce.js`

```js
/**
 * 防抖 —— 连续触发时只执行最后一次
 * @param {Function} fn - 要执行的函数
 * @param {number} delay - 等待时间（毫秒）
 * @returns {Function} 防抖后的函数
 */
export function debounce(fn, delay = 300) {
  let timer = null
  return function (...args) {
    if (timer) clearTimeout(timer)
    timer = setTimeout(() => {
      fn.apply(this, args)
      timer = null
    }, delay)
  }
}

/**
 * 节流 —— 固定时间间隔内只执行一次
 * @param {Function} fn - 要执行的函数
 * @param {number} interval - 时间间隔（毫秒）
 * @returns {Function} 节流后的函数
 */
export function throttle(fn, interval = 500) {
  let lastTime = 0
  return function (...args) {
    const now = Date.now()
    if (now - lastTime >= interval) {
      lastTime = now
      return fn.apply(this, args)
    }
  }
}
```

> 📖 **防抖 vs 节流**：
> - **防抖**：像电梯等人——等最后一个人进来才关门。适合：搜索输入、窗口 resize。
> - **节流**：像游戏 CD——技能冷却中按了也没用。适合：滚动加载、拖拽。

**在 UserManage.vue 中的应用**：

```js
import { debounce } from '@/composables/useDebounce'

// 搜索按钮防抖（防止快速连点）
const handleSearch = debounce(() => {
  currentPage.value = 1
  getManageData(keyword.value, currentPage.value, pageSize.value)
}, 300)
```

如果以后要做"输入即搜"（搜索框 `@input` 触发），直接把 `@input="handleSearch"` 绑定上去就行，防抖已在内部处理。

### 4.4 `usePage` —— 分页逻辑

**现状问题**：UserManage.vue 里 `currentPage`、`pageSize`、`total` 三个变量 + 切换逻辑写在一起，如果其他页面也要分页就得重写。

**封装方案**：`src/composables/usePage.js`

```js
import { ref } from 'vue'

/**
 * 分页逻辑 composable
 * @param {Object} options
 * @param {number} options.defaultPage - 默认页码，默认 1
 * @param {number} options.defaultSize - 默认每页条数，默认 10
 */
export function usePage({ defaultPage = 1, defaultSize = 10 } = {}) {
  const currentPage = ref(defaultPage)
  const pageSize = ref(defaultSize)
  const total = ref(0)

  /**
   * 页码切换
   * @param {number} page - 新页码
   */
  function onPageChange(page) {
    currentPage.value = page
  }

  /**
   * 重置到第一页
   */
  function resetPage() {
    currentPage.value = 1
  }

  return {
    currentPage,
    pageSize,
    total,
    onPageChange,
    resetPage
  }
}
```

**改造 UserManage.vue 时整合使用**：

```js
const { currentPage, pageSize, total, onPageChange } = usePage()

// 绑定到 el-pagination
// <el-pagination :current-page="currentPage" :total="total" :page-size="pageSize"
//   @current-change="onPageChange" />
```

## 5. 请求层封装

### 5.1 请求拦截器 —— 自动注入 Token

**现状问题**：`request.ts` 的请求拦截器是空壳，登录后发出的请求不会携带 token（因此后端无法识别身份）。

**改造 `src/request.ts`**：

```js
import axios from 'axios'

const instance = axios.create({
  baseURL: 'http://localhost:3001',
  timeout: 10000,
  headers: { 'Content-Type': 'application/json' }
})

// ---------- 请求拦截器 ----------
instance.interceptors.request.use(
  function (config) {
    // 从 localStorage 获取 token，注入请求头
    const token = localStorage.getItem('token')
    if (token) {
      config.headers.Authorization = `Bearer ${token}`
    }
    return config
  },
  function (error) {
    return Promise.reject(error)
  }
)

// ---------- 响应拦截器 ----------
instance.interceptors.response.use(
  function (response) {
    // 直接返回 response.data，省去各处写 .data
    return response.data
  },
  function (error) {
    // 统一处理网络错误
    const message = error?.response?.data?.message || '网络错误，请稍后重试'
    ElMessage.error(message)       // 注意：需要在 main.js 全局注入 ElMessage
    return Promise.reject(error)
  }
)

export default instance
```

> ⚠️ **注意**：响应拦截器中要用 `ElMessage`，而 `ElMessage` 需要在 `main.js` 中全局挂载才能在没有 `<script setup>` 的文件中使用。方式如下：

```js
// main.js 中
import { ElMessage } from 'element-plus'
app.config.globalProperties.$message = ElMessage
// 或者直接在 request.ts 中 import ElMessage（element-plus 支持这种方式）
```

### 5.2 响应拦截器 —— 统一解包 & 统一报错

**效果对比**（改造前 vs 改造后）：

**改造前 —— 每个 API 调用处都要手动解包**：

```js
const res = await userLogin({ username, password })
if (res.data.code === 200) {
  ElMessage.success('登录成功')
  userStore.login(res.data.data.token, res.data.data.user)
  router.push('/')
} else {
  ElMessage.error(res.data.message || '登录失败')
}
```

**改造后 —— 响应拦截器代劳**：

```js
const res = await userLogin({ username, password })
// res 已经是 res.data 了
if (res.code === 200) {
  ElMessage.success('登录成功')
  userStore.login(res.data.token, res.data.data.user)
  // 等等，这里还是有 res.data —— 需要后端格式配合
}
```

**更彻底的方案 —— 让拦截器直接提取 data**：

后端返回格式：`{ code, message, data: { token, user } }`

如果 `code === 200`，直接返回 `response.data.data`（即 `{ token, user }`）；
如果 `code !== 200`，统一弹错并 reject。

```js
instance.interceptors.response.use(
  function (response) {
    const body = response.data
    if (body.code === 200) {
      return body.data   // 直接剥到 data 层
    }
    ElMessage.error(body.message || '请求失败')
    return Promise.reject(body)
  },
  function (error) {
    const message = error?.response?.data?.message || '网络错误，请稍后重试'
    ElMessage.error(message)
    return Promise.reject(error)
  }
)
```

**改造后的 API 调用**：

```js
// api/user.js
export const userLogin = async ({ username, password }) => {
  return await instance.post('/api/login', { username, password })
}
```

```js
// Login.vue
const { token, user } = await userLogin({ username, password })
userStore.login(token, user)
router.push('/')
```

从 ~15 行变成 ~3 行，而且**错误处理完全统一**。

但要注意：
- 这种方式要求后端返回格式完全统一（本项目已经做到了 ✅）
- 如果某些接口需要拿到完整的 `{ code, message, data }`，可以加一个 `raw: true` 参数控制，或者直接调 `axios.get` 不走拦截器

**折中方案 —— 只解一层**：

```js
// 拦截器只剥到 response.data，不剥到 data
instance.interceptors.response.use(
  function (response) {
    const body = response.data
    if (body.code !== 200) {
      ElMessage.error(body.message || '请求失败')
      return Promise.reject(body)
    }
    return body   // { code, message, data }
  },
  // ...
)
```

这样 API 调用处写 `if (res.code === 200)` 而不是 `if (res.data.code === 200)`，省掉一层 `.data`。这是风险最小的改造，建议你先用这个。

## 6. 组件封装

除了 composable，还有两种常见的封装方式：

### 6.1 通用弹窗组件

UserManage.vue 的 "新增/编辑用户" 弹窗内容很多，可以抽成独立组件：

```vue
<!-- src/components/UserFormDialog.vue -->
<script setup>
import { ref, watch } from 'vue'

const props = defineProps({
  visible: Boolean,
  mode: { type: String, default: 'add' },   // 'add' | 'edit'
  initialData: { type: Object, default: () => ({}) }
})

const emit = defineEmits(['update:visible', 'submit'])

const form = ref({ ... })

function handleSubmit() {
  emit('submit', { ...form.value })
}
</script>
```

使用处：

```vue
<UserFormDialog
  v-model:visible="dialogVisible"
  :mode="isEditMode ? 'edit' : 'add'"
  :initial-data="editData"
  @submit="handleFormSubmit"
/>
```

### 6.2 通用 Table 组件

如果未来多个页面都需要表格展示 + 分页 + 搜索，可以把 `el-table` + `el-pagination` 封装成 `AppTable` 组件。

**但别过度封装** —— 如果只有 UserManage 一个页面有表格，保持原样就好。

> 💡 **封装原则**：**三次法则** —— 同一个模式出现 3 次以上才考虑抽成通用组件。2 次用 composable 就够了。

## 7. 完整改造路线图

下面是从现状到封装完成的逐步改造计划，按**风险从小到大**排列：

### 第一阶段：纯新增（无风险）

| 步骤 | 内容 | 影响范围 |
|------|------|---------|
| 1 | 建 `src/composables/` 目录 | 无 |
| 2 | 写 `useInputLimit.js` | 无（等引用） |
| 3 | 写 `useKeyboardSubmit.js` | 无（等引用） |
| 4 | 写 `useDebounce.js` / `useThrottle.js` | 无（等引用） |
| 5 | 写 `usePage.js` | 无（等引用） |

### 第二阶段：改造组件（中等风险）

| 步骤 | 内容 | 影响范围 |
|------|------|---------|
| 6 | Login.vue 改用 `useInputLimit` + `useKeyboardSubmit` | Login.vue |
| 7 | Register.vue 改用 `useInputLimit` | Register.vue |
| 8 | UserManage.vue 改用 `useKeyboardSubmit` + `usePage` + `debounce` | UserManage.vue |

### 第三阶段：改造请求层（需回归测试）

| 步骤 | 内容 | 影响范围 |
|------|------|---------|
| 9 | 请求拦截器注入 token | 所有 API 请求 |
| 10 | 响应拦截器统一弹错 + 解一层 `.data` | 所有 API 调用处需检查 |
| 11 | 清理 API 调用处多余的 `.data` | `Login.vue` `Register.vue` `UserManage.vue` `UserCenter.vue` |

> ⚠️ **第三步建议单独一个分支做**，因为会触及所有页面，改完后需要逐个页面手工测试。

## 总结

```
封装前                   封装后
─────────────           ─────────────
Login.vue  ~120 行      Login.vue    ~80 行
Register.vue ~180 行    Register.vue ~120 行
request.ts  空壳         request.ts  有拦截器
每个 API 处重复 .data    API 调用更简洁
composables/ 空          composables/ 5 个文件
```

封装不仅是让代码变少，更是让**每个文件的职责变清晰**：
- 组件文件 → 只关注 UI 和交互
- composables → 只关注逻辑复用
- request.ts → 只关注网络请求

下一步就是照上面的路线图一步步动手改。每个 composable 都可以独立写、独立测试，互不干扰，非常适合分步推进。
