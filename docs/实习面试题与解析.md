## 第二轮:项目深挖(重头戏,占面试一半时间)

### 1. 整体讲一下项目:前后端怎么分工?9 个接口分别干什么?

**解析**:项目是前后端分离。前端 Vue 3 负责页面与交互,后端负责数据与鉴权,通过 HTTP 接口(JSON)通信。
9 个接口(记住,面试官可能让你背):
| 接口 | 方法 | 作用 |
|---|---|---|
| /api/login | POST | 登录,返回 token + 用户信息 |
| /api/register | POST | 注册 |
| /api/users | GET | 分页 + 关键字搜索用户列表 |

### 2. Axios 拦截器做了什么?token 怎么注入?401 时你做了什么?

**解析**:
- **请求拦截器**:每次请求前从 Pinia store 拿 token,存在就拼到请求头 `Authorization: Bearer <token>`——不用在每个接口里手动加
- **响应拦截器**做两件事:
  1. **统一业务判断**:后端约定返回 `{code, message, data}`,`code === 200` 才算成功,否则弹错误提示并 reject——页面不用重复写错误处理
  2. **统一 HTTP 错误**:没有响应(网络错误)提示"检查后端是否启动";**401 表示登录过期 → 调用 store.logout() 清登录态 + 跳转登录页**;其他状态码弹后端返回的 message
- 登录/注册接口特殊处理:错误原因(如"用户名或密码错误")必须让用户看到,但不做登出跳转

### 3. 登录状态刷新后为什么不丢?Pinia + localStorage 怎么配合?

**解析**:
- Pinia 是内存状态,刷新页面就清空
- 项目用了 `pinia-plugin-persistedstate`,store 配置 `persist: true`,状态( token + userInfo )自动同步到 localStorage
- 刷新后插件自动从 localStorage 恢复数据,所以登录态不丢
- 可以提一句:**只用 Pinia 不加持久化,刷新就会回到登录页**——这个对比能体现你真的理解

### 4. 路由守卫:怎么做到"管理员才能进用户管理页"?

**解析**:
- 在路由配置的 `meta` 里打标:`requestAdmin: true`(用户管理)、`requestGuest`(登录页)、`requestUser`(个人中心)
- `router.beforeEach` 全局守卫,每次跳转前检查:
  - `requestAdmin`:已登录**且** `userInfo.role === 'admin'` 才放行,否则提示"需要管理员权限"并跳回首页
  - `requestUser`:有登录态(userInfo)才放行
  - `requestGuest`:已登录用户再访问登录页,直接踢回首页
- **诚实补充点**(面试官必追问):前端判断 role 只是"隐藏入口",防君子不防小人——篡改 localStorage 的 role 就能绕过,所以真正安全靠**后端接口鉴权**(后端每个管理接口都校验角色)。项目后端(Express 版)是简单实现,你正在用 Spring Boot 重写,会在后端做真正的权限控制——这正是你重写项目的动机。

### 5. 分页 + 搜索怎么实现的?为什么要写防抖?

**解析**:
- 请求 `/api/users` 带三个参数:`keyword`(搜索词)、`page`(页码,从 1 开始)、`pageSize`(每页条数),后端返回 `{total, list}`,前端用 total 渲染分页器
- **防抖 useDebounce**:搜索框每敲一个字符都发请求会打爆接口。防抖 = 停止输入一段时间(如 500ms)后才执行——把"连发的请求"合并成"最后一个"
- 搜索和分页联动:切换页码时带上当前 keyword;修改关键字后重置回第 1 页

### 6. 新增/编辑共用同一个弹窗,怎么区分两种模式?

**解析**:
- 弹窗组件通过 prop 传 `mode`(`'add'` / `'edit'`)或直接传当前编辑对象
- 区分点:**新增** = 空表单 + 提交调 addUser;**编辑** = 表单回显(把该用户数据填进表单)+ 提交调 updateUser
- 好处:表单布局、校验规则只写一份,减少重复代码(简历里写了这一点,要能讲出来)

### 7. 项目怎么部署到 GitHub Pages?为什么用 hash 路由?

**解析**:
- 本地 `npm run build` 打包 → dist 目录推到 GitHub Pages;或配 GitHub Actions:push 到 master 自动 build + 发布
- **hash 路由**(URL 带 `#`):GitHub Pages 是纯静态托管,没有服务器做路由回退。history 模式刷新 `/user/userManage` 时服务器找不到这个路径会 404;hash 模式请求的永远是 `#` 前面的路径(如 `/index.html`),刷新也不会 404——所以静态托管必须用 hash

### 8. (追问)JWT 是什么?你能讲清楚吗?

**解析**(用大白话讲):
- JWT = 登录成功后后端发的"带签名的通行证",是三段字符串(header.payload.signature),里面存了用户 id/用户名,后端用密钥签名
- 之后每次请求把 JWT 放 `Authorization` 头里,后端验签通过就认你是谁——不用每次查数据库
- 前端只需要:登录拿到 token → 存起来 → 请求时带上 → 401 说明过期 → 清掉重新登录

## 第三轮:Vue 3 基础

### 1. Composition API 和 Options API 区别?

**解析**:Options API 按类型组织代码(data/methods/computed 分块);Composition API 按**功能/逻辑**组织,用 setup 函数 + ref/reactive 等 API 写。组合式 API 优势:同一功能的代码聚在一起,逻辑可以抽成自定义函数(useDebounce、usePage)复用;复杂组件更清晰。你的项目用了 Composition API。

### 2. ref 和 reactive 区别?为什么 ref 要用 .value?

**解析**:
- `reactive` 只能处理对象,直接 `obj.xx` 访问,响应式是深层的
- `ref` 能包任意类型(基本类型、对象),访问必须 `.value`——因为基本类型没法直接做响应式,必须包一层对象,`.value` 就是取包里的值;模板里会自动解包,所以模板中不用写 `.value`
- 选型:基本类型用 ref,对象用 reactive(或都用 ref,项目里 store 的 token 就是 ref)

### 3. computed 和 watch 区别?

**解析**:computed 是**根据已有数据计算新值**、有缓存、依赖不变不重算,用在模板渲染的派生数据;watch 是**监听数据变化执行副作用**(发请求、操作 DOM 等)。项目例子:store 里 `isLoggedIn = computed(() => !!token.value)`;watch 场景如"页码变化时重新拉数据"(也可以用 watch 或事件触发)。

### 4. v-for 为什么要有 key?

**解析**:key 是每个节点的唯一标识,让 Vue 在更新列表时能**复用已有节点**而不是全部重建。用 index 当 key 的坑:列表中间插入/删除时,后面元素的 key 全变,可能导致复用错乱(如输入框内容错位)。正确做法:用数据里唯一的 id。

### 5. 组件通信方式有哪些?项目里用到哪些?

**解析**:props 父传子 / emit 子传父、provide+inject(跨层级)、Pinia(全局共享)、v-model、event bus(少用)。
项目里:登录状态是全局的 → Pinia;弹窗组件靠 props/emit;页面 → 组件传参用 props。

### 6. 你理解的"数据驱动视图"是什么?

**解析**(浅层即可):声明式地描述"数据长什么样,页面就长什么样",不手动操作 DOM。数据变了,Vue 的响应式系统检测到 → 更新对应的 DOM。好处:代码只关心数据,不用自己 appendChild/改 innerHTML。Vue 3 底层用 Proxy 拦截数据读写 + 虚拟 DOM diff 来高效更新页面——讲到这层实习面试就超额完成了。

## 第四轮:JavaScript + HTML/CSS 基础

### 1. let / const / var 区别?

**解析**:var 函数作用域、可重复声明、会变量提升(可"预访问"undefined);let/const 块级作用域、不可重复声明、有暂时性死区(声明前访问报错);const 声明后不能再赋值(对象内部属性可以改)。现在写代码用 const 优先,需要重新赋值才用 let,不用 var。

### 2. Promise 是什么?async/await 和它什么关系?

**解析**:Promise 是 JS 处理异步的"包装对象",三种状态 pending/fulfilled/rejected,状态一旦确定不可变。解决回调地狱:链式 `.then/.catch`。async/await 是 Promise 的语法糖:async 函数返回 Promise,await 等它完成后把结果"解出来",让异步代码像同步一样读。
项目里:axios 本身返回 Promise,`await instance.request(...)` 就是用它;拦截器里 `Promise.reject` 把错误抛给调用方。

### 3. 闭包是什么?防抖函数用到了闭包吗?

**解析**:闭包 = 函数 + 它**记住的外层作用域的变量**。即使外层函数执行完,内层函数仍能访问那些变量。防抖正是典型:防抖函数内部保存 `timer`,返回的新函数每次调用都能拿到同一个 timer 并重置它——这个 timer 就是被闭包记住的变量。项目里 useDebounce 就是这个原理。

### 4. 手写题:数组去重 / 防抖 / flex 居中

**数组去重**(至少会两种):
```js
// 方式一:Set(最简单)
const unique = [...new Set(arr)]

// 方式二:filter + indexOf(只留第一次出现的位置)
const unique = arr.filter((item, i) => arr.indexOf(item) === i)

// 方式三:reduce + includes
const unique = arr.reduce((acc, cur) => acc.includes(cur) ? acc : [...acc, cur], [])
```

**防抖**(能写出来):
```js
function debounce(fn, delay = 500) {
  let timer = null
  return function (...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)
  }
}
```

**flex 垂直水平居中**:
```css
.parent { display: flex; justify-content: center; align-items: center; }
```

### 5. 浏览器从输入网址到看到页面,简述过程?

**解析**(说个大概):输入网址 → DNS 解析成 IP → 浏览器发起 HTTP 请求(建立 TCP 连接)→ 服务器返回 HTML → 浏览器解析 HTML 生成 DOM 树、解析 CSS 生成样式 → JS 执行 → 渲染成页面。能说出 DNS、HTTP 请求、渲染三步就算过。

## 第五轮:工程基础

### 1. 跨域是什么?本地开发 5173 访问 3001 为什么能通?

**解析**:跨域 = 浏览器安全策略(同源策略),协议/域名/端口任一不同,浏览器默认拦截响应。你的项目没有配 Vite proxy,是**后端开放了 CORS**:后端允许了 `http://localhost:5173` 这个源(Express 用 cors 中间件 / Spring Boot 配 CorsFilter),响应头带上 `Access-Control-Allow-Origin` 等,浏览器看到就放行。
可以补一句:CORS 实际是**浏览器**的拦截,不是服务器拒绝;复杂请求(如带自定义头 Authorization)会先发一次 OPTIONS 预检请求确认允许。

### 2. Git 平时怎么提交?分支冲突遇到过吗?

**解析**:`git add` → `git commit -m "描述"` → `git push`;写清楚 commit 信息(做了什么,如"修复登录过期不跳转的问题")。冲突:两个人改了同一处代码,merge 时冲突,需要打开冲突文件手动决定保留哪部分,再提交。可以说:冲突不可怕,关键是**先看清楚两边改的是什么**。

### 3. 线上页面打开慢,从哪些方向优化?

**解析**(说 2-3 个即可):
- 首屏:路由懒加载(按需加载页面)、代码分割、图片压缩/懒加载
- 请求:合并请求、缓存(HTTP 缓存/CDN)、防抖节流
- 构建:Tree-shaking 去掉没用代码、资源上 CDN
实习生答出"首屏加载 + 图片 + 缓存"已经不错。

## 第七轮:AI Agent(你的差异化卖点,重点准备)

> **开讲前先背这一段总述**(面试官问"你用 AI 干活吗"时,直接甩这个框架):
>
> "我的用法不是让 AI 一键生成整个项目,而是把它当团队里的执行者,我当工程师。固定五步循环:① 概念和需求我先自己搞懂,看不懂的不开工;② 把需求拆成 3-5 个可独立验证的小任务;③ 每个任务交给 AI 实现,写完我逐段 review,看不懂就让它解释;④ 每完成一个任务,用接口契约验证(curl/浏览器逐条对);⑤ 阶段结束复盘:哪里踩了坑、下次怎么避免。核心原则:**任务拆得越小,我越能控制质量**。"

### 1. 你和 AI 怎么分工?

**完整回答**(可背):"我拆需求、定契约、做验收,AI 写实现代码。比如后端重写:我先把 9 个接口的契约定死——路径、方法、参数、返回格式,AI 只能按契约实现,做完我逐条验证。简单说:**决策和验收是我的,执行是它的**。"

**追问应对**:
- 追问"那你不是啥都不用干了?"→ "恰恰相反,拆需求和验收是**最难**的部分。拆错需求,AI 就写错;不会验收,AI 写错了我也发现不了。AI 把我的工作量从'写代码'变成了'设计 + 审查',不是变没了"
- 追问"AI 和人有什么区别?"→ "人会偷懒会情绪化,AI 不会;但人懂业务上下文,AI 不知道。所以业务判断我负责,重复性执行交给它"

### 2. AI 写的代码你看得懂吗?怎么保证?

**完整回答**(可背):"看得懂,靠两个保证:① **任务拆得小**——一次只让 AI 写一个文件、一个接口,代码量小,我有精力看 ② **逐段 review + 追问**——每段关键代码都让它解释'为什么这么写',我能讲出来才放行,讲不出来就继续问,直到懂为止。**看不懂的代码不放行**,要么问清楚,要么自己重写——这是底线,不然就是埋雷。"

### 3. AI 写错了你怎么发现?

**完整回答**(可背):"靠**契约驱动验证**。接口契约在写代码之前就是定死的——路径、HTTP 方法、状态码、返回字段。AI 写完,我启动服务,用 curl 和浏览器逐条对着契约测,返回不符合契约就是它错了,让它改。**验证是对着'期望行为'核对,不是看代码'感觉对不对'**。"

**加分细节**(实际抓出来过的,面试官爱听具体的):
- 后端分页 page 从 1 开始,JPA 默认从 0——这类边界契约就是逐条测出来的
- 时间格式契约:`createdAt` 必须是 `yyyy-MM-dd HH:mm:ss`,默认会带 T,不对就抓出来

### 4. 什么时候不用 AI?

**完整回答**(可背):"三种情况:① **反复改不对**——说明它根本不理解需求,这时候该自己读代码,而不是继续耗 ② **业务关键决策**——风险高、需要我完全掌控的环节自己来 ③ **它生成的代码我审查不了**的时候。另外我的体会是:**AI 是放大器**——我自己越懂,AI 越有用;自己什么都不懂,AI 只会帮我堆出一堆我看不懂的 bug。"

### 5. 你用 AI 做过哪些事?(面试官问"除了写代码还用来干嘛"时)

**回答**:列能力 + 一句总结:
- 代码生成:接口、组件、配置
- 解释代码:看不懂的实现让它讲
- 代码审查:让 AI 帮我找 bug、挑毛病
- 任务并行:多个独立小任务同时推进
- 报错分析:把报错信息丢给它快速定位
- 面试模拟:让 AI 当面试官考我,答不上来的题立刻补
- 总结句:"它不是换个地方搜索,而是能承担**执行**和**审查**两个角色——这也是我和只会'复制粘贴 AI 代码'的人的区别"

### 6. 讲一个具体靠 AI 解决问题的例子(讲成故事)

**故事模板**(套真实案例):问题(遇到了什么)→ 拆解(我把它拆成什么小任务)→ AI 做了什么 → 我怎么验收(契约/curl/浏览器)→ 结果 + 我学到什么。

**现成素材(后端重写,选一个练熟)**:
- 素材 A(技术选型):重写后端需要 Spring Boot 3.5.16,但官方生成器已下架 3.x 只有 4.1.1 → **我拍板**手动搭 3.x 骨架,理由:3.x 资料和报错可搜性最好 → AI 按需求执行搭建 → 验证 `/api/hello` 返回 200 → 学到:**版本这类技术决策是我的活,AI 只负责执行**
- 素材 B(环境问题):JDK 装完但 Maven 构建找不到 Java → 查了发现 JDK 装在了用户目录而不是默认位置 → 让 AI 分析,定位到需要显式设置 JAVA_HOME → 解决。学到:报错要先自己看懂再让 AI 帮定位,不然连问题都描述不清

### 7. agent 轮避坑注意事项(必看)

1. **绝对不说**:"这代码全是 AI 写的"——面试官直接判定简历注水,前功尽弃
2. **反复强调**:需求是我拆的、契约是我定的、错误是我抓的——**AI 是执行者,决策和验收是我**
3. **用词**:说"AI Agent 驱动开发"比"用 AI 写代码"高级;能解释 agent 和普通 AI 助手的区别更好——agent 是**能自主执行多步任务**的 AI(拆任务→执行→验证→迭代),不是问一句答一句
4. 简历写的是 Trae,面试时把**工具名弱化、方法论强化**:"日常用 Trae,但更关键是这套拆任务、定契约、逐条验收的方法,换 Claude Code 也能用"
